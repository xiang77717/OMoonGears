## 总体技术路线

### 功能描述

确定整机技术路线：遥控手动方案、双机配置，"运动—收集—收纳"的功能分解，以及最终的整机构型。

### 为什么这样做（选型理由）

1. **选手动而非自动**：经调研后得出结论——最好不要搞全自动，半自动的界限都比较模糊，直接做手动。9 月 27 日晚进一步确认：场内比赛若做全自动，现有技术条件容易直接失败，因此整场比赛按手动操控设计。
2. **自动降级带来视觉降级**：不做全自动，对视觉的要求大幅降低。赛方不提供视觉培训（培训视频只有电控、机械、硬件），因此视觉组转为储备，刘苗淼主攻机械基础，9/28 晚正式转入机械组。
3. **双机配置**：赛场设红 1、红 2 两个启动区，需两台机器人。经讨论（9 月 27 日晚）确定两台为**同一种类型**，最多再加一台备用；不做"收集机 + 干扰机"的异构组合。
4. **成本约束驱动材料选型**：总成本限 400 元，比赛对抗强度低，故材料以3D 打印件为主，不使用昂贵的碳板；节省下的经费投入到电机组件上。
5. **构型取舍的最终依据——重量与时效**：多轴坐标系方案的滑轨重量过大，实验证实两个滑轨都好重了，不得不抛弃；而低车体铲收方案结构件少、大量可 3D 打印、对强度要求低，因此在 9/30 被重新提出后成为主线。
6. **功能分解**：根据比赛任务理解，将"运动—收集—收纳"的功能分解为"运动—收集"和"运动—收纳"的功能，分别对应低车体铲收方案的"挖掘臂"和"收纳盒"。

### 方案定型过程（9/28 → 10/16）

**第一阶段：两台各试一型。** 9/28 晚决定做两台，夹持处"一个做夹子、一个做气囊针"，用实物对比敲定。

**第二阶段：转向挖掘机方案。** 9/30 晚杨粤辉提出新思路——放弃"精密抓取"，改做**挖掘机式铲收**：底盘前方一个收纳盒，一把能扣住地面的铲子直接把方块往回扒拉；个别扣在洞穴里的方块用探针扎出来。算是最省时的一个方案

**第三阶段：两案融合定稿。** 10/1 队内就"四分核心能否拿到""是否要做升降""方块会不会被推着跑"等等逐条交锋后达成融合：

> **台阶上的扒进去，地面的推进去。**

**第四阶段：双车分化（10/16）。** 机械组讨论后调整：1 号车回到传统机械臂抓夹路线，2 号车保留低车体铲收；方案由"单一铲收"转为"两车各一型"并行验证，形成以下两套定稿构型。

**定稿构型（一）：传统机械臂抓夹式（1 号车）**

| 部件   | 方案                                         |
| ---- | ------------------------------------------ |
| 车体   | 整体压低，**旁侧作为收集空间**                        |
| 收集   | 中间布置**挖掘臂**（双关节、三自由度），行进时收折、到位展开扒拉         |
| 转向   | 全向底盘                                       |
| 辅助   | 保留**夹爪**，用于取藏在中孔/洞穴里的方块                    |
| 配重   | 可选，车体做得小而重，保证不能被撞开                         |
| 战术备选 | 利用臂的灵活性取挂杆、洞穴等非平地方块利用 |

**定稿构型（二）：低车体"篮子"式铲收机器人（2号车）**

| 部件   | 方案                                  |
| ---- | ----------------------------------- |
| 车体   | 整体压低以通过桥下 130 mm；顶部布置机械臂与收纳盒，重心尽量靠中 |
| 抓取   | 机体下方的收纳仓两侧安装环抱式抓夹，“抱”进方块   |
| 收纳   | 机身下部设置收纳腔 + 单向口，方块只进不出，防低速挤压抢夺      |
| 转向   | 全向底盘                                |
| 配重   | 车体做得小而重，保证只能被挤压、不能被撞开               |
| 战术备选 | 与 1 号铲车分工覆盖不同地形 |

## 抓握机构（手部）

### 功能描述

直接与方块接触、完成"拾起"动作的末端机构。方块为 11.3 g中空立方体（内径 15 mm），抓握需可靠、快速，并与后续收纳动作衔接。

### 方案演进（三种原始方案 → 两候选 → 铲收定型）

9 月 26 日，杨双铖提出三种抓握方案并附手绘草图：

1. **气囊膨胀式**：碳纤杆锥形探针插入方块中孔 → 注气使气囊膨胀撑住内腔 → 移送 → 放气释放。气筒由舵机驱动，结构可充气可吸气。
2. **线驱夹持式**：绞线牵引的夹爪闭合夹取。
3. **铲式**：舵机驱动翻斗上拉铲起方块，再翻转倒出。

机械组加深了对fusion360的认识，能完整完成草图描摹，实体建构，会使用3D打印机，对标准件加深了解

9 月 27 日讨论后收敛为气囊探针与传统夹持两个候选；**9/30 起铲收思路被重新提出并升级为整机方案，成为主线**（见"总体技术路线"），气囊探针降级为取洞内方块的辅助手段，夹持方案搁置。**10/16 双车分化后，夹持方案在 1 号车上重启，采用传统机械臂抓夹式。**

### 为什么这样做（对比与论证）

**气囊探针派的理由（杨双铖、施湘宜）：**

- 探针本身细，容易插入 15 mm 的中孔；插入后气囊膨胀即从方块**内部**将其撑起，对表面无要求。
- 相比夹子需要夹持面与夹持力控制，探针对方块姿态的适应性更好。
- 气筒与气囊构成密闭气路：压气筒则气囊膨胀，收针筒则气囊收回，释放靠放气完成，动作简洁。
- 气囊伸缩的运动范围比只能上下移动的简易机械臂更广。

**质疑与反思：**

- 气囊同样需要精确定位，且存在**时效问题**：充气—放气是一个过程，对付挂在杆上的方块时，先刮落、再插针、再等气囊张开，总时长可能长于直接夹取。
- 9/28 打印实物后，杨双铖实测视角后仍认为"站着看就比较难操控"。

**铲收派的理由（9/30 起，杨粤辉主导）：**

- 方块**大量不在平地上**，与其逐个精密抓取，不如用铲子成片扒拉，单位时间收益高。
- 比赛是抢分赛，收集速度优先于收集精度。
- 结构件少、可大量 3D 打印；能量核心很小很轻，**不必过多考虑机械稳固性**，重量也随之下降。

**对铲收的质疑与化解：**

- 施湘宜：对电控要求是否过高 → 最终采用单平面自由度的单轴臂，机械实现难度低。
- 杨双铖：球类靠弹力绳引导，方件无引导，铲子笨重、往届全是平地作业 → 改为"低车体篮子 + 单向口"，地面方块直接推入，不再依赖铲刃精准托举。
- 杨双铖：方块很轻，容易被推着走 → 承认此风险，用"‘抱‘进单向口"替代"铲到铲子上"。

### 开发历程

- 9/26 下午：三方案手绘草图完成，团队讨论后认为方块仅 11.3 g，不存在拉不动的问题，抓握力要求很低。
- 9/27 下午：确认方块中空（内径 15 mm），探针直径约 5–10 mm 即可，棒子可用 3D 打印自制；杨粤辉提醒不能抛弃原有机械臂设计，因为不确定操作手精度高不高。
- 9/28 早：围绕气囊定位与时效性展开辩论，转入实物测试。
- 9/28 下午：赴交创打印 30 mm 立方体实物，确认孔隙可插入手指，验证探针方案物理可行。
- 9/30 晚：铲收思路回归并升级为主线。
- 10/1 凌晨：确认能扒拉方块儿就行，铲子只是类比。
- 10/12 进行3D打印，而打印机出现问题，需要重新打印。
- 10/14 下午：发现开源项目的机械大臂比预期中短，杨双铖调整了一下建模并做了一点设计
- 10/16 中午，经机械组内讨论，1号车做传统机械臂夹爪设计，2号车做铲车设计，并开始机械臂的组装，但未安装在车身上。
- 10/18 下午：根据实际面包板的摆放，完成机械臂的安装。

## 定位与搬运机构（臂 / 坐标系）

### 功能描述

承载抓握手部、把方块移动到收纳位置的空间运动装置，是整机方案的核心分歧点。

### 方案演进

**候选 A：机械臂式** —— 抓取后向上旋转，松手使方块落入收纳盒。关节做单向运动即可。
**候选 B：坐标系式（类抓娃娃机）** —— 底部滑轨负责左右、立起滑轨负责上下，横竖两轴运动；立轴上装手部，舵机转动齿轮控制探针伸缩。
**最终方案：低车体铲收 + 中间单轴挖掘臂** —— 定位机构不再需要精确对位，改为在车体中间布置一个只有一个平面自由度的扒拉臂。

### 为什么这样做（对比与论证）

- **坐标系派理由（杨双铖）**：从机械结构上看比机械臂简单；三舵机调控对电控要求提高，但**对这种比赛而言精度会比机械臂大幅提升**——操作手没有机器的第一视角，只能在旁边看，且方块很小，笛卡尔坐标系的定点投放比关节臂的估测投放更可控。
- **机械臂派理由**：场地内有方块挂在杆子上，机械臂相对灵活；纯坐标系方案对侧向空间要求大。
- **风险对冲**：杨粤辉指出把所有希望寄托在坐标系上太冒险，故两个方案长期并行评估。
- **坐标系的出局（9/30 晚）**：经实测确认**两个滑轨都重量超标，不得不抛弃**。项目限重 2.0 kg，滑轨自重占比过高。
- **机械臂的问题（9/27 起）**：小成本小机器精度不足；上限精度很高，但有限时间内做不出来。
- **铲车方案的两次命运**：9/27 因23 个方块中 11 个不在地上、方件无引导、铲子笨重、往届全为平地作业而被否决；**9/30 晚以"收纳盒 + 单向口"的改良形态回归，成为主线**。

### 难点与解决方案

- **难点 1：释放动作**。解决思路：气囊方案"运动到指定位置之后把气收了"，靠重力滑入收纳盒；铲收方案靠单向口自然落入收集腔。
- **难点 2：机械臂上抬速度**。若上升过快，结构冲击大，还可能把方块甩出去。解决方案：采用**递进式控制**——写程序让机械臂按百分比步进运动，平滑升臂。
- **难点 3：侧向干涉**。机械臂左右旋转在某些位置转不开（场地障碍），故臂只做向上单向旋转，水平移动交给底盘。
- **难点 4：调转车头不便**。10/1 讨论确认，场地过道仅约 30 cm，掉头困难；解决方案是在底盘下加一个可四面转向的圆盘，使扒拉臂能对准任意方向而无需整车掉头。
- **难点 5：限高与超高**。车体展开后需满足 ≤445×400×450 mm 或 550 mm 球体约束，讨论中两次提到"超高了"，需在建模阶段卡死。

### 开发历程

- **9/26 晚｜初版构型**：确定"机械臂上升 + 下方收纳盒"的整体方案，定位与抓握按解耦设计。
- **9/28 早｜风险对冲**：队长判断全押坐标系太冒险，两方案继续并行；机械组同步论证气囊的适用范围与时效。
- **9/30 晚｜坐标系出局**：实测确认两条滑轨自重过大，占 2.0 kg 限重比例过高，坐标系方案淘汰，转向挖掘机式铲收。
- **10/1 凌晨｜融合定稿**：围绕"四分核心能否取得、是否加升降、方块会不会被推走"逐条辩论，形成"台阶上的扒进去，地面的推进去"；定位机构简化为车体中间的单平面自由度挖掘臂。
- **10/14 下午｜建模修正**：发现开源机械臂大臂比预期短，杨双铖调整建模并补充设计。
- **10/16 上午｜双车分化**：机械组讨论后确定 1 号车做传统机械臂夹爪、2 号车做铲车。

## 收纳与运输机构

### 功能描述

存储已收集的方块并在停赛时保有它们。该功能直接对应核心计分规则。

### 为什么这样做（选型理由）

- **防抢夺是首要约束**：规则"只计算停赛时携带在身上的方块"，且允许对方低速挤压、抢运输中的方块。因此收纳机构必须做成**单向口**，方块只进不出，即使被低速挤压也无法被取出。
- **单向口的具体实现（10/1 确定）**：采用**单向阀 / 单向开口**，开口尽量做低，地面方块可直接推入，进入后无法反向掉出。
- **收纳位置随整机方案而定**：方案一中收纳盒放在旁边独立的槽内，机械臂方案中置于机身最前方；行进时铲臂收折，到位后展开取物。

### 开发历程

- **9/26 下午｜需求推导**：只计停赛时携带在身上的方块，直接推出单向口需求——方块只进不出，防对方挤压抢夺。
- **9/27 晚｜两套预案**：随臂/坐标系两方案并行，分别确定"机身内部上方"与"旁边独立槽"两种收纳盒布置。
- **10/1 凌晨｜定稿**：确定为车体中间凹陷+单向阀，同时解决"收纳盒放前面就只能挖前面、扒拉不到旁边"的布置争议。
- **10/13 上午|协商**：需要与电控方面协调，确认具体排线方案，从而决定实际的机身结构。
- **10/14 下午｜改变**：根据电控方面反馈，电线占有空间目前无法压缩，碍于高度和时间紧迫性，最后确认机身结构具体实现为**单向阀 + 旁侧凹陷做收纳**。
- **10/15 下午|决定收纳设计**：机械组经过讨论，决定收纳盒采用瓦楞纸板。
- **10/17 下午|实操**；根据实际面包板的摆放，完成收纳盒的安装。
- **10/18 下午|完成全车组装**

## 底盘与移动系统

### 功能描述

整机平面移动机构，负责场内机动、接近方块、穿越限高地形与实施低速对抗。

### 为什么这样做（选型理由）

- **轮系选型（10/6 定论）**：队长在实验室实测一台四轮底盘小车，移动顺滑；讨论初期考虑场地小、障碍多、对抗中需灵活变向，倾向**万向轮**（四轮本质只适合直线为主的行驶）。10/6 最终定为全向底盘（麦克纳姆轮），机动性好
- **低车体是最终方案的硬需求（10/1）**：车体需要压低以穿过**桥下 130 mm 净高**，同时与 150 mm 台阶形成高度差，便于从台阶上扒拉方块。讨论中还据此推演出"若对方车体高于 130 mm 则过不了桥，可被堵路"的战术。
- **转向方式**：因过道仅约 30 cm，整车掉头困难；10/6 定为全向底盘（麦克纳姆轮），用全向移动实现原地变向，不再额外加四面转向圆盘。
- **质量分布要求**：若配重或机构分布不均，很可能连直线都走不直，故布局需保证质量均匀。

### 开发历程

- **9/26 晚｜方案起步**：队长分享实验室四轮小车视频，全队讨论底盘构型与机动需求。

## 视觉识别（储备方向）现已放弃

### 功能描述

用摄像头识别场上方块并输出坐标，作为全自动/半自动的储备能力。因整机确定走手动路线，本方向不进入主线。

### 开发内容

已独立实现脚本 `cube_detect.py`，功能如下：

| 项目   | 内容                                                       |
| ---- | -------------------------------------------------------- |
| 目标   | 识别黄色（能量核心）与白色（能量单元）方块，输出相对画面中心的像素偏移与面积                   |
| 方法   | 锁定相机曝光 / 增益 / 白平衡 → HSV 阈值分割 → 形态学开闭运算 → 按面积、矩形度、长宽比过滤轮廓 |
| 调参   | 鼠标点选方块自动采样 HSV 阈值，可分别应用到黄 / 白，支持 mask 预览窗口               |
| 过滤参数 | 面积 1500 \~ 画面 20%，矩形度 ≥0.60，长宽比 0.60\~1.70（用于排除白墙、桌沿）    |
| 实测   | 640×480，曝光 -2 时约 3.5 fps，白色阈值像素占比 13.11%                 |

串口输出协议（115200）：`$<目标数>|<颜色>,<序号>,<dx>,<dy>,<面积>|...#`，例 `$2|Y,0,-120,45,10000|W,0,30,-80,4900#`。颜色 Y=黄、W=白；序号按同色从左到右从 0 开始；dx/dy 为相对画面中心的像素偏移；无目标时发 `$0#`。

### 为什么这样做

- 黄色与白色是场内唯一的两类计分道具，且方块为纯色、背景为白色地胶，HSV 分割足以区分，无需训练模型。
- 相机自动曝光与自动白平衡会持续改变饱和度与亮度，而 HSV 判据是绝对阈值，故必须锁定相机参数，否则画面内容一变阈值就失效。
- 核心难点在**光照**：本机实测中曝光 -2 时帧率仅 3.5 fps，靠增益补亮的代价是噪声，根本解法是加装白光 LED 补光。
